# 多智能体协作 Demo · 测试用例

> 覆盖范围：团队组建 → 广播任务自主协作（拆解 → 认领 → 板序串行接力 → 完整交付）→ 数据流 → @指派 → 边界异常 → UI 细节
> 优先级：P0 核心路径（答辩必演）｜P1 重要分支｜P2 细节体验
> 「自动化」列：✅ = 已由 Playwright E2E 覆盖（场景 A/D/C/E），空 = 手动执行

## 模块一：团队组建（首页）

## 模块二：广播任务 · 自主协作（核心）

| 编号 | 用例 | 优先级 | 前置条件 | 操作步骤 | 预期结果 | 自动化 |
|---|---|---|---|---|---|---|
| TC-10 | 发送广播消息启动协作 | P0 | 团队含调研+写作+代码+战略 | 输入「针对智能音箱市场做调研分析，并写产品文案」→ 发送 | 输入框上方出现进度带：发布→认领→执行→验收→完成 逐步点亮 | ✅ |
| TC-11 | 选择性认领（轻语） | P0 | 同上 | 观察认领阶段 | 调研/写作/战略各出现一条认领轻语（含匹配度%）；调研 94%、写作 81%、战略标「验收方」 | ✅ |
| TC-12 | 未匹配者不认领 | P0 | 同上 | 观察代码智能体 | 全程零轻语；右栏徽标显示「未认领」（置灰） | ✅ |
| TC-13 | 认领逐个出现 | P1 | 同上 | 观察轻语出现节奏 | 各轻语间隔约 0.5s 依次出现（体现各自决策），非一次性弹出 | |
| TC-14 | 依赖排序：信息先于生产 | P0 | 同上 | 观察回复顺序 | 调研回复完成后写作才开始「正在思考」；代码全程无回复 | ✅ |
| TC-15 | 板序串行执行（无并行） | P0 | 团队含产品/代码/设计 | 发送「如何实现一个记账APP」 | 回复严格按板序：需求梳理(产品) → 技术实现(代码) → 界面设计(设计)；板上箭头=执行顺序 | ✅ |
| TC-16 | 执行中成员发光 | P1 | 任意执行中任务 | 观察右栏 | 正在执行的成员头像呼吸发光；同层并行时多个同时发光 | |
| TC-17 | 每个认领者完整产出 | P0 | 任意多领域团队 | 发送广播任务并等待完成 | 所有认领者各产出一条正式完整回复（战略/产品按能力认领如「需求梳理」，不再只做验收） | ✅ |
| TC-18 | 生成时自动补全 | P1 | 任务含「产品文案/公告/邮件」 | 发送任务并查看产出 | 占位符在生成时自动填充（无退回环节），产出无 [未填] 残留（如「目标用户」→「目标用户群体」） | ✅ |
| TC-19 | 收束线统计 | P1 | 任务完成后 | 查看收束线 | 「协作完成 · N 人协作 · M 项产出」；有子任务无人认领时注明「X 个子任务无人认领」 | ✅ |
| TC-20 | 进度带生命周期 | P1 | 任意广播任务 | 观察任务结束后输入框上方 | 进度带点亮「完成」后整体淡出消失，不留在聊天流 | ✅ |
| TC-21 | 执行日志完整叙事 | P1 | 任务完成后 | 查看右栏执行日志 | 按序含：任务发布 → 各成员评估/认领 → 执行顺序 → 开始验收 → 退回/修订 → 验收结论 → 任务完成 | ✅ |
| TC-22 | 认领徽标状态 | P1 | 认领阶段/结束后 | 查看右栏成员徽标 | 认领者「认领 · N%」（靛紫）、未认领者「未认领」（灰）；任务后保留至下次任务 | ✅ |

## 模块五：边界与异常

| TC-35 | 模糊任务兜底 | P1 | 任意团队 | 发送「帮我搞一下那个事」（无关键词命中） | 全员评估后未认领；对话智能体兜底承接（或其默认回复即澄清提问） | |
| TC-36 | 子任务无人认领 | P1 | 团队无对应领域成员 | 发送含多子任务的任务 | 该子任务跳过执行，收束线注明「X 个子任务无人认领」 | ✅ |

| TC-39 | 处理中输入锁定 | P1 | 任务执行中 | 尝试再次输入发送 | 输入框与发送按钮禁用，不能并发发送 | |
| TC-40 | 切换团队状态隔离 | P1 | 有 ≥2 个团队 | 任务进行中/完成后切换团队 | 各团队消息独立；成员徽标回落为角色名；日志独立 | ✅(D4) |

| TC-42 | 清空聊天/日志 | P2 | 有历史消息 | 点击「清空」 | 聊天记录清空显示欢迎态；日志清空显示「暂无日志」；刷新后不恢复 | |
| TC-43 | 删除当前团队 | P1 | ≥2 个团队，停留在待删团队 | 左栏菜单删除当前团队 → 确认 | 自动跳转到列表第一个团队，中间区域正常显示，无矛盾空态 | |
| TC-44 | 旧版本数据升级 | P2 | localStorage 存有 v4 及更早数据 | 直接打开应用 | 旧消息/日志被清理（版本机制）；**团队列表保留**；无报错 | |
| TC-45 | 空消息防御 | P2 | 任意团队 | 空内容/纯空格点击发送 | 不发送，无异常 | |
| TC-46 | 任务拆解 + 对板认领（开发类任务） | P0 | 团队含调研/产品/代码/写作/设计 | 发送「如何实现一个记账APP」 | 拆解线「需求梳理 → 技术实现 → 界面设计」；产品/代码/设计各认领对应子任务（拆解展开隐含需求）；调研/写作沉默；按板序串行产出 3 项完整交付 | ✅ |
| TC-47 | 拆解线仅多子任务时展示 | P1 | 任意团队 | 发送单意图任务（如「写一份产品文案」） | 板仅 1 个子任务时不显示拆解线，直接认领执行 | ✅(E3) |

## 自动化覆盖对照

Playwright E2E（44 项断言）对应关系：

- **场景 A**（全栈团队广播任务）→ TC-10/11/12/14/15/17/18/19/25/28
- **场景 D**（刷新持久化）→ TC-41/40
- **场景 C**（@直通）→ TC-30
- **场景 E**（单子任务板）→ TC-47/27
- **场景 F**（任务拆解+板序串行·用户实测场景）→ TC-46/15/17

其余用例为手动执行项（组队流程、@选择器、清空/删除、渲染类型等）。
